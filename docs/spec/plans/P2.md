# P2 plan — Training mode

## Goals

On the practice screen a learner picks Listen or Training, a hand (right, left or both), a
speed (40–120%) and optionally a bar range to loop. In Training, playback runs to the next
notes for that hand, holds with those keys lit ("Waiting for G4 B4") until they are played,
then carries on. A metronome and a one-bar count-in can be switched on. One practice
engine does all of this, with a policy per mode, so P6 can add performance mode without
touching steps, matching, speed or loop. No schema change, no pipeline work, no new
dependencies.

## Checked in a real browser

The built app was driven in headless Chrome with the real Tone.js transport, the real Web
MIDI adapter and a virtual MIDI port injected into the page (scripts kept out of the repo).
No console errors or exceptions in any run.

- **Training, right hand, Twinkle:** all 14 steps hold and resume; the readout moves on
  within 15 ms of the key; wrong notes don't move it on; "10 of 14 right first time" after
  four deliberate wrong notes; the song ends and Play comes back.
- **Training, both hands at 60%:** 14 chords and notes, 16.1 s for a 9.6 s song (9.6 ÷ 0.6 = 16).
- **Training, left hand, loop bars 1–2 with count-in:** count-in, three steps, count-in,
  three steps, and so on; "6 of 6 right first time" after two passes.
- **Listen at 120%:** 8.05 s for the song (9.6 ÷ 1.2 = 8).
- **Listen, loop bar 1 with metronome:** wraps every 2.4 s; pause holds the position.
- **Audio scheduling** (every Web Audio source start was logged): in Listen the 14 note
  onsets are on the song's 0.6 s grid to the millisecond, each scheduled at least 40 ms
  ahead, and the 16 metronome clicks sit on the same grid. In Training, Isai's other-hand
  note is scheduled at the audio time of the learner's key (so it sounds at once) when the
  key comes after the hold, and at the step's own time when the key comes early.

Two things this showed that the fakes could not:

- The readout said "Count-in…" again for about 100 ms after the first step that follows a
  count-in, because the phase was read from the transport position, which runs behind the
  engine by Tone's lookahead. Fixed (`fix(engine)`), with a test on a lagging transport.
- A hold is announced (keys lit, "Waiting for …") one lookahead, about 100 ms, before the
  sound actually stops. A key pressed in that window counts as on time. This is harmless and
  left as it is.

## Differences from the plan

- **A Listen mode sits next to Training.** The spec's mode switch has Training and
  Performance. Listen is P1's playback on the new engine (no holds, both hands sound), so
  P1's behaviour is still there and the screen works with no keyboard. It is the default.
- **"While holding, nothing sounds" is read as "nothing new sounds".** Notes already
  sounding ring on through a hold; cutting them off at every step sounded like a fault.
- **Notes outside the learner's keyboard are not expected.** A 49-key learner can't be
  made to wait for a note they don't have. The keyboard-size choice feeds the engine, and
  the out-of-range message says training skips those notes.
- **Right and wrong marks are shapes, not colours.** The spec asks for a success token and
  an error token; the design system is greys only (STYLE_GUIDE rule 3). A right key gets a
  disc, a wrong key a disc with a cross, from two new fixed piano tokens
  (`--piano-correct`, `--piano-wrong`).
- **The readout has more than "Waiting for …".** It also says "Next: G4" while playing,
  "Count-in…", "Paused", and after a run "Press Play to go again." with the count of steps
  played right first time.
- **A hint asks for a keyboard in Training** when none is connected through the panel.
- **Metronome and count-in are off by default.** The spec doesn't say.
- **The loop picker is a toggle and two bar pickers.** "Loop bars 1–4" is the toggle's
  label; From and To appear when it is on. A song with no beats shows times instead.
- **Speed is kept in whole percent** in the page, so stepping never drifts off the 5% grid.
- **The rule 5 test checks more than the spec asks:** each slice of the run is its own
  `act()`, so a stray state update would show as a commit at once; exactly one commit
  happens, when the song ends.
- **`.alert-quiet` alone had no padding** (a P1 slip the review missed). Alerts now use
  `.alert.alert-quiet`. A disabled segment (`.seg-btn:disabled`) has its own style.
- **The transport row is two lines:** buttons and time, then the position slider.
