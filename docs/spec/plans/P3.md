# P3 plan — Analysis core

## Goals

`isai analyse song.mp3 --type full-mix --out out/` decodes real audio and writes a valid
Song (schema 0.2.0) with real beats, downbeats, bpm, time signature, key, mode, scale and
confidences, plus a MIDI file with the tempo map. Notes and chords stay empty. A stage
runner caches each stage, and the first real golden-eval report is committed. Pipeline
only, apart from one web change: the bar helper uses `tempo.downbeats`.

## Approval

After "proceed with further development" on 2026-11-14, P3 was taken as the next phase:
it is the only one whose dependencies are met (P8 needs P5). The owner approved this plan
the same day as written: ADR 0008 is accepted, the schema change and the dependencies are
approved, the spike may install its candidates in its own environment, and ffmpeg was
installed with winget (ffmpeg 9.0.2). The golden audio is still to come. What was asked:

1. **ADR 0008, schema evolution** (`docs/adr/0008-schema-evolution.md`, `proposed`): the
   policy the architecture spec recommends. `schemaVersion` becomes an enum of supported
   versions; additive optional fields bump the minor version; breaking changes bump the
   major and ship JSON migrations on both sides.
2. **The schema change:** optional `tempo.downbeats` (seconds), version `0.2.0`, with
   `0.1.0` still accepted.
3. **Pipeline dependencies:** `numpy`, `scipy`, `librosa` (with `numba` and `llvmlite`,
   together about 60 MB), `soundfile` (about 2 MB) and `mido` (small). No separate loudness
   library: integrated loudness (EBU R128) is about 60 lines of numpy in
   `ingest/loudness.py`, tested against reference tones.
4. **The beat-tracking spike** runs in its own environment under `pipeline/spikes/beats/`,
   so the candidates' dependencies stay out of the pipeline until the ADR picks one.
   Candidates:
   - **Beat This!** (a neural beat and downbeat tracker, PyTorch). Needs `torch`: about
     2.5 GB with CUDA on this laptop's RTX 4050, about 200 MB CPU-only.
   - **madmom's RNN + DBN**: madmom is unmaintained and hard to install on Python 3.11 and
     Windows. If it won't install, I'll say so and use a maintained RNN/DBN port instead,
     or drop it from the comparison with the reason.
   - **`librosa.beat`**: the baseline, no downbeats (bar phase estimated from onset
     strength).
   - Each model's weight licence goes into the ADR; non-commercial weights are flagged as
     blocking a public launch.
5. **ADR 0009, beat tracking and key finding**, written after the spike with its numbers,
   for you to accept along with whichever model dependency it brings.
6. **System dependency: ffmpeg ≥ 6 is not installed on this machine** (`ffmpeg` isn't on
   `PATH`). I can install it with `winget install Gyan.FFmpeg` if you allow it, or you can
   install it yourself. The README will document it either way.
7. **Golden audio (yours):** at least 6 songs (2 piano-solo, 2 full-mix, 2 a-cappella) in
   `tests/golden/manifest.yaml`, with expected key, mode and bpm. Audio stays outside git
   (rule 8). The spike and the golden-eval exit criterion wait for these; everything else
   can be built and tested on synthesised audio first.
8. **Branch:** `p3-analysis` is cut from `p7-notation` (stacked like P6 and P7), because
   the one web change edits P2's bar helper. Alternatively, merge P1, P2, P6 and P7 into
   `main` first and cut P3 from there.

## Design decisions (mine to make; listed so they can be questioned)

- **Stages are plain functions over typed dataclasses** (`isai/<stage>/types.py`). The
  runner (`isai/runner.py`) wires them per source type, times each one and writes JSON-line
  logs with `--log-json`. Stages don't read files or global config.
- **Cache:** `.cache/<audio-hash>/<stage>-<stage-version>-<options-hash>/`, numpy arrays
  in `.npz` and the rest in JSON. `--no-cache` ignores it; `--from-stage` re-runs from a
  named stage onward. The cache stays gitignored and holds no audio beyond what
  `ingest` produced (P8's worker clears it per job).
- **Ingest:**
  - ffmpeg decodes to mono float32 at 44.1 kHz through a pipe (no temp audio files), and
    resamples a 22.05 kHz copy.
  - Loudness is normalised to −23 LUFS in numpy.
  - Silence is trimmed at −60 dBFS (RMS over 50 ms), keeping the offset so every time in
    the Song matches the original audio.
  - Limits: duration over 12 minutes or input over 100 MB → exit 5; no ffmpeg or a decode
    failure → exit 4; silence → exit 6.
  - The cache key is the SHA-256 of the decoded PCM, never stored in the Song.
- **Rhythm:**
  - A `BeatTracker` protocol returns beats and downbeats.
  - Pure functions compute bpm (median inter-beat interval), time signature (3 or 4 from
    downbeat spacing, otherwise 4 with low confidence), stability (the coefficient of
    variation of the intervals) and `confidence.tempo`.
  - `librosa.beat` is the first tracker, so the pipeline works end to end before the spike.
- **Tonality:**
  - Chroma comes from the CQT of the harmonic part (HPSS), weighted by beat-synchronous
    energy and shifted by the measured tuning offset in cents.
  - `theory/keyfinding.py` (pure) holds the Krumhansl–Kessler, Temperley and
    Albrecht–Shanahan profiles. The key is the best summed z-scored correlation over 24
    keys, with confidence from the gap to the runner-up.
  - `mode = modal` when the best major and minor candidates are close and neither fits
    well (thresholds set on the synthesised tests, revisited on the golden set).
  - `scale` comes from `theory.scales`.
- **MIDI out** (`isai/midi_out.py`, mido): type 1. Track 0 has a tempo change at every
  beat, so a DAW's bar lines follow the song, plus the time signature and key signature.
  Tracks 1 and 2 hold the right and left hand (empty in P3).
- **Determinism:** times rounded to 1 ms, fixed seeds, and sorted output. A test runs
  the same input twice and compares the bytes.
- **Song:** `meta.confidence.chords` stays 0 (no chords yet); `notes` and `chords` are
  empty; `durationSec` is the original audio's length.

## Tests

- **Ingest** (audio synthesised in `tmp_path`; MP3, FLAC and M4A where ffmpeg encodes
  them): sample rate, mono downmix, loudness within ±1 LU, the silence-trim offset,
  too long, silent, a non-audio file, ffmpeg missing.
- **Loudness:** reference tones against known LUFS values (BS.1770 test signals).
- **Rhythm:** click tracks at 60, 90, 120 and 174 BPM in 3/4 and 4/4; a tempo ramp
  (flagged unstable); derived values on hand-made beat lists.
- **Key finding:** I–IV–V–I progressions in all 24 keys, synthesised and detuned by
  ±30 cents; the relative-key confusion case; an empty chroma; each profile.
  `theory/` ≥ 90% lines.
- **Runner:** stages run in order per source type; the cache skips finished stages and
  `--no-cache` re-runs them; `--from-stage`; timings and JSON logs.
- **CLI:** `--type` required, `carnatic` refused, every exit code.
- **Determinism:** byte-identical Song and MIDI twice (`slow` if it uses a model).
- **MIDI:** the tempo map, time signature and key signature read back with mido.
- **Schema:** 0.1.0 and 0.2.0 examples load on both sides; the frozen 0.1.0 example stays
  valid.
- **Web:** the bar helper with and without downbeats; 0.1.0 and 0.2.0 Songs parse.

## Differences from the plan

- **The dependencies are bigger than estimated:** about 280 MB installed, not about
  60 MB. llvmlite (116 MB) and scipy (89 MB) are most of it, and librosa also pulls in
  scikit-learn (29 MB). These are the same packages you approved.
- **Repeatable output needs `--id` and `--created-at`.** A Song's `id` and `createdAt`
  would otherwise be a random id and the current time. Deriving the id from the audio hash
  would have put a content fingerprint in the Song, which the spec keeps out. So both are
  inputs (the P8 worker will pass the job's), and with both fixed the output is
  byte-identical, cached or not.
- **The librosa tracker's downbeats** come from the bar length (3 or 4) and phase whose
  beats carry the strongest onsets. This is a stopgap until the spike's tracker, which
  gives downbeats itself.
- **Key confidence and the modal threshold** were set on synthesised material: full
  confidence at a 0.3 correlation lead; "modal" when the best major and minor keys are
  within 0.08 and neither fits above 0.6. Both get revisited on the golden set.
- **librosa's first call in a process compiles with numba** (3–19 s). It's counted in the
  runtime figure above.
- **`/golden-eval`** now passes each song's `--type` to `isai analyse`.
