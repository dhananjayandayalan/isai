# P6 plan — Performance mode

## Goals

A learner plays a song or a loop straight through, Isai never waits, and afterwards a
Results page shows the score, timing, each hand, each section and the trouble spots, with
one click to loop a trouble spot in training. Timing is corrected by a latency offset the
learner measures by tapping along to clicks. Settings and past sessions are kept on the
device. Web only: no schema change, no pipeline work.

## Tests

- **Scorer:** perfect play; everything 80 ms late; jitter (seeded); missed notes; extra
  notes; chords partly played; the same pitch twice in a window; a loop pass boundary;
  speed 50% (windows unchanged in heard time); latency offset applied; an empty song; a
  single note; a run finished early; sections and four-bar phrases; trouble spots.
  Golden files: fixed event streams give fixed result JSON.
- **Engine:** a performance run of each example song; no holds; count-in always; loop
  passes scored; Finish; the lit keys move on by time; listen and training unchanged.
- **Calibration:** a known injected offset is measured within ±5 ms with `FakeMidiInput`
  and `FakeTransport`; outliers; too few taps.
- **Stores:** defaults when empty, corrupt or throwing; sessions survive a new store on
  the same database (a reload); fallback to memory when IndexedDB throws.
- **DOM:** a performance run of each example song ends on a Results page whose per-hand
  and per-section numbers match a hand-checked fixture; trouble-spot loop in training;
  sessions listed on the overview; calibrate from the latency card; the app works when
  `localStorage` and IndexedDB throw.
- **Rule 5:** a full performance run causes no React commit until it ends.
- **Lint guards:** `Date` is allowed in `sessions/wallClock.ts` and nowhere else.

## Differences from the plan

- **Pause ends a performance.** A scored run is one take, so while it plays the Play
  button becomes **Finish**, and the speed, loop, hands, mode, keyboard size and position
  slider are locked. Changing what is played abandons the run (ADR 0006).
- **The last keyboard reconnects on the next scan**, not at startup. Asking for MIDI
  access can show a permission prompt, so it still waits for "Find my keyboard".
- **The timing histogram has a hand filter** (both, right, left) instead of two charts.
- **Two fixes from the DOM tests:** the keyboard panel is hidden, not unmounted, on the
  Results page (it holds the connection), and the practice screen reports play and stop
  to the app in the same commit as its own state.
- **Not driven in a real browser yet.** P2 was checked in headless Chrome with a virtual
  MIDI port; P6 so far only with the fakes. The owner's by-hand check covers it.
